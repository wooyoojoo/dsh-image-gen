# 用 on-twos 做 2D 动作动画

这份文档记录一套**用生成模型做 2D 动作游戏动画**的方法，全部结论来自本仓库工具链上的实测（`tools/` 那五个脚本），不是通用动画教材的复述。目标是独立游戏量级：一个角色、十几个动作、要能进引擎。

## 1. 概念：时间轴 ≠ 作画张数

- **时间轴**是播放密度（电影 24fps、游戏 60fps）；
- **on ones / on twos** 说的是**作画密度**：
  - **on ones** = 每 1 格换一张新画 = 24 张/秒
  - **on twos** = 每 2 格换一张 = **12 张/秒**（日语「2コマ打ち」，业界默认）
  - **on threes / fours** = 8 / 6 张/秒
- 所以"12 帧做法"不是"一秒画 12 张"，而是"**一秒有 12 张可用，每张停几格由你排**"。

**为什么默认 on twos**：张数减半＝成本减半；手绘线条在 24 张/秒下会"沸腾"（逐帧微差被读成闪烁），12 张/秒的步进反而更稳、更有手绘味；步进本身提供"snap"。**这条对 AI 生成同样成立，而且更强**：模型逐帧之间的差异比人手更大，on ones 密度下必然闪烁。

**与文件格式的关系**：GIF 的延迟单位是 1/100 秒，而 24fps 的一格是 1/24s = 4.1667 厘秒，**除不尽** —— GIF 只能近似 24fps 网格。APNG 的延迟是**分数**（`delay_num/delay_den`），`1/24` 可以原样写进去。所以：

```sh
node tools/make-apng.mjs --out=anim.png --exposures=5,2,7,1,4,5 frames/   # 精确
node tools/make-gif.mjs  --out=anim.gif --exposures=5,2,7,1,4,5 frames/   # 近似（21,8,29,4,17,21）
```

## 2. 曝光表：每张画停几格

手绘动画的核心工具是**曝光表（exposure sheet）**：左列"格"，右列"用第几张画"，同一张画连写几格 = 停几格。`--exposures=` 就是这张表，单位是 **24fps 的格**。

行业惯例不是"全片 on twos"，而是**逐张决定曝光格数**：

> 对话 on twos、停顿 on threes~fours、极快动作临时切 on ones、慢动作 on eights。

打击感的标准曲线（实测有效）：

| 段 | 曝光 | 作用 |
|---|---|---|
| 起手待机 | 4–6 格 | 让观众看到"要打了" |
| 抬/蓄力 | 2 格 | 比两头都快，制造动量 |
| **预备停顿** | 6–8 格 | **打击感的一半在这里** |
| **出手那一帧** | **1 格（on ones）** | 快到看不清 |
| **命中定帧** | 3–5 格 | **另一半打击感** |
| 收势 | 5–7 格 | 缓慢回位，接上循环 |

参考实测（铁盆砸人，6 帧素材）：`--exposures=5,2,7,1,4,5` = 24 格 = 精确 1.00 秒。同一组帧换成均匀 13/100s（总长几乎一样）后，力度明显变弱 —— **差别全在节奏上，不在帧数上**。

## 3. AI 生成版的额外规则（这份文档的核心）

### 3.1 一张精灵图 6 帧是实际上限

`1536x1024` 的画布排 3×2，每格 512px —— 这刚好装下一个 Q 版角色加道具。实测：单行 6 帧（256px 格）会因为格子太窄而**跨格溢出**（接缝墨迹高达 178px，角色头发的自然宽度就有 250px）；4×2（384px 格）勉强；3×2（512px 格）是甜点。

想更长的动作**不要加画**，要靠**停顿**（同一张画停 6–8 格很常见）。真要 12 帧以上，就得两张图拼接，而**跨图一致性会明显变差**。

### 3.2 快段只能放一张画

实测：7 帧版把「smear + 原本的中割」都放在快速段各停 1 格 → 动起来**明显抖动**；改成 smear 独占快段（6 帧版）→ 稳。

> **原则**：「删掉中割」的意思是**恰好一张 smear 顶上**，不是"smear 再加原本的中割"。
> **判据**：快帧之间要么姿态差别极大，要么处理手法差别极大；坏掉的永远是"几乎一样、但画得略有不同"的那种。

### 3.3 中割用 smear 顶上（而且描述要写对）

smear = 一张**故意糊掉/拉长**的过渡画。它的额外好处：**它本来就是模糊的，所以对跨帧一致性的要求最低** —— 恰好落在图像模型最擅长的区间（画一张"运动模糊的挥击"，不需要和邻帧严丝合缝）。

**prompt 写法的实测教训**：

- ✅ 正面描述"一条"：*"ONE continuous curved motion trail… a single smooth tapered swoosh… thickest where the basin is, fading out along its length, soft blurred edges like a long brush stroke or a comet tail"*
- ❌ 不要写"两三张残影副本"：*"two or three faint ghosted copies"* —— 我这么写过，模型就真画了一叠半清晰的盆，很怪
- 并加排除句：*"no separate copies, repeated outlines or ghosted duplicates; it is motion blur, not an afterimage stack"*

### 3.4 VFX / 冲击反馈不要烘焙进角色序列

这条最重要，也很容易走错：**冲击反馈属于受击方**，不属于攻击方。

把白闪、碎片、冲击波画进角色序列的后果：

1. 同一套攻击动画**不能复用于不同受击物**（打铁盆、打水、打木桩，反馈强度都该不同）；
2. **风格容易跑**：实测烘焙版画出了硬边白色放射爆 + 晶状碎片，和 Q 版柔和赛璐璐画风明显不搭；
3. 角色序列变长，而**这类效果本该由引擎按受击材质叠加**。

正确分工：

| 层 | 归属 | 手段 |
|---|---|---|
| 角色动作 | 角色序列（on twos） | 6 帧精灵图 + 曝光表 |
| 闪白 | 引擎 | 给精灵 tint 到白 1–2 帧（着色器），不烘焙 |
| 顿帧 | 引擎 | 命中瞬间冻结整个游戏 2–6 渲染帧（含特效/镜头） |
| 镜头震动 | 引擎 | 2–4 帧衰减位移 |
| 打击特效 | 受击物 / 独立特效精灵 | 2–3 帧的效果图，**跑 60fps**，与角色 12fps 形成对比 |
| 受击反应 | 受击方动画 | 击退、压扁、旋转 —— **打击感有一半来自"被打的东西"** |
| 音效 | 引擎 | 低频重击 + 命中前一瞬静音 |

### 3.5 单独生成的帧必须做尺度归一化

换帧用的补充帧（smear、受击、道具变化）通常是**单独生成**的，模型会按自己的构图把它画满画布 —— 实测出现过角色比序列帧**大 1.5–1.9 倍**的情况，直接插进去就是"瞬间膨胀"。

归一化要用**对拖影/形变免疫的特征**：

- ❌ 剪影/包围盒/头带宽度：smear 的头发被速度拖宽（实测 897px vs 序列 335px），指标量的是"拖影"不是"角色"
- ✅ **脸部肤色连通域面积**：对头发拖影免疫，实测可用（7743px → 目标 3447px → 缩放 0.667）

流程：量特征 → 算线性系数（面积比开平方）→ 缩放 → **再拼条带人眼复核**（数值只能保证量级，眼睛才能确认）。

这一步已经固化成工具：

```sh
node tools/normalize.mjs <单独生成的帧> --to=<邻居帧.png>[,...] --out=scaled.png
node tools/strip.mjs  --out=compare.png 邻居1.png scaled.png 邻居2.png   # 人眼复核
```

## 4. 一条完整的制作流程

```
① 定版帧：单帧、独占整张画布，把"版型"钉死（头身比 / 镜头 / 握法 / 道具结构 / 画风）
      ↓  插件里就是 animationSet + animationRole:"key"；后续所有帧都继承它
② 精灵图：3×2 六帧，一张图保证比例与画风一致，随机性只剩"动作"
      ↓  插件里就是 layout:"3x2" + animationRole:"frame"（定版帧自动挂成第一张参考图）
③ 切片：tools/slice.mjs —— 按空白找刀口 + trim + **脚底锚点**对齐
      ↓  锚点是"视点固定"的关键：实测按包围盒对齐时脚底锚点抖动 56px，按脚底锚点对齐后为 0
④ 单帧手术：tools/frame-tool.mjs —— crop → 单独重画 → paste（先擦格子再贴，否则重影）
      ↓
⑤ 补充帧：smear / 道具变化帧，单独生成后走 §3.5 的尺度归一化
      ↓  tools/normalize.mjs --to=<邻居帧>
⑥ 曝光表：--exposures= 排节奏（§2）
      ↓
⑦ 预览与交付：APNG 预览（无损、精确时序）；引擎交付用 PNG 序列 + 曝光表 JSON
         --manifest=exposure.json 直接导出后者
```

## 5. 成本参考（实测单价，gpt-image-2.5 / high / 1536×1024）

| 项 | 成本 |
|---|---|
| 一张 6 帧精灵图（含两张参考图输入） | **≈ $0.057** |
| 单独一帧（1024²，含参考图） | **≈ $0.05** |
| on twos（12 张/秒）当量 | 2 张图/秒 ≈ **$0.11/秒动画** |
| on ones（24 张/秒）当量 | 4 张图/秒 ≈ $0.23/秒动画，且跨图一致性无法保证 |
| 骨骼/网格路线（Spine 等） | 一张分解图 $0.05，之后零生成成本 |

结论：**要"手绘步进味"→ AI 关键帧 + 曝光表（on twos 是甜点）；要"丝滑 60fps"→ 拆件 + 骨骼**，不要靠堆帧数。

## 6. 坑清单（速查）

- 模型**总把角色放大到填满每一格**，"四周留宽阔空白"这条指令无效 → 边距只能后处理补
- **否定式指令守不住**："不要看镜头"经常失效 → 改成正向、可判定的"视线朝向身体前方的对手，瞳孔明显偏离观众"
- **参考图要声明分工**："第二张仅作镜头角度参考，不要复制它的角色/画风/配色"
- **头身比要靠参考图带**：文字描述压不住，最好把设定图的正视图裁出来单独当"比例参考"
- **道具结构要写死**：提手要"两端穿过盆沿的两个小耳、明显连接、不许悬空"这类结构描述，否则会出现悬空把手
- **GIF 的延迟 < 2 会被浏览器钳制成 100ms** → 快帧给 ≥5/100s
- **APNG 序号规则**：首帧 `fcTL(0)+IDAT`，之后 `fcTL(1)+fdAT(2)`、`fcTL(3)+fdAT(4)`…（所以 fcTL 序号是 0 与奇数）
- **sharp 不报 APNG 帧数**（只读静帧），浏览器原生会播
- **GIF 只有全透明/全不透明**：抗锯齿边缘必须二值化；实测一张透明帧有 **42–45% 的像素带部分透明**，这些在 GIF 里都会变成硬边
- **生成的图会随检出目录消失**：切好的帧、拼好的动图要落到工程目录里，不要留在临时目录
